# 平台运维铁律（174实测）

以下每条都对应一次真实踩坑。**改平台前先读这一页。**

## 1. 「端口 bound」不等于「服务可用」

代理型服务（反向代理 / relay / 上游转发）的上游死后，**监听套接字仍在**，
每个请求返回 502。任何 `is_listening()` 式检查都会永远报健康。

**必须打一次真实 HTTP 请求并要求 200。**
判据：`bound 但非 200 且本地无监听` → 清stale 进程重建。

## 2. unit 源目录 ≠ 生效目录

改 `systemd/*.service` 后不生效，journal照常打印旧文件内容。
必须 `cp` 到 `~/.config/systemd/user/` 再 `daemon-reload`。
校验：`systemctl --user show <unit> -p FragmentPath`。

## 3. 历史事故：is-active 说 active 不等于服务活着

`Type=oneshot` 的unit 里脚本 nohup 拉子进程后自己退出，systemd 认为仍 active，
**子进程崩溃 systemd 完全不知情**（实测 kill -9 后仍报 active）。
判据以端口为准。timer 驱动的 service 在两次运行之间本就该inactive。

## 4. supervisor 日志在 journald，不在 `$LOG_DIR/*.log`

只有 healthcheck **timer** 写 `dl/healthcheck.log`；
supervisor 自愈记录在 journal：
`journalctl --user -u vcc-backlog.service | grep ISOLATED HEAL`

> 在 dl/*.log 里grep 找不到 ≠ 自愈没生效。这个误判我犯过一次。

## 5. `$NOTES_PROJECT` 是软链

它指向 `MyTask/memory`。`find` 默认**不跟随软链** → 数出 0 篇笔记，
症状像「数据全丢」。用 `find -L` 或直接查 `$PLATFORM_ROOT/memory`。

## 6. 面板由代理注入，按绑定地址分别验证

127.0.0.1:6422 是裸 board（无面板）；
<LAN_IP>:6422 与 <TAILSCALE_IP>:6422 经 kb-proxy.py 注入。
验面板要访问对应代理 origin；本机裸 board 看到 0 个标记是预期行为。

## 7. 注入到别处的 HTML，链接必须绝对

面板被拼进6422 后，根相对 `/api/note` 会解析到**看板自己的 origin** → 404。
症状极欺骗：**面板渲染正常、条目就在眼前，点进去 Not Found**。
`vcc-readonly.py` 的 `VCC_BIND_IP` 就是为此存在。

## 8. 绝不要 `pkill -f "<脚本名>"`

会连执行它的 ssh shell 一起杀掉 → exit 255、后续命令全不执行，
症状像「上传成功但部署没生效」。
**按端口反查 PID**：`ss -tlnp | grep ":PORT "` 后用正则 `pid=(\d+)` 取。
注意同一端口可能有两个进程（127.0.0.1 的 board + 公网 IP 的注入代理）。

## 9. git 绝不放 NFS

**先分清哪个路径在哪块盘上**（2026-10-06 实测）：

| 路径 | 实际位置 | 文件系统 |
|---|---|---|
| `/mnt/zhangth` | `<LAN_IP_2>:/Backup` | **nfs4** |
| `/mnt/zhangth/projects` | → `$PLATFORM_ROOT/platform` | **ext4**（软链） |
| `$PLATFORM_ROOT/*` | `/dev/sdb` | **ext4** |
| `$NFS_MOUNT` | `<LAN_IP_2>:/Backup` | **nfs4** |

**平台仓库其实在 ext4 上** —— `/mnt/zhangth/projects` 只是指向它的软链。
把它当 NFS 会得出错误结论（例如误以为 worktree 隔离是性能必需）。

但「git 不放真 NFS」这条依然成立：2026-10-06 实测 30 次小文件写，
`/mnt/zhangth`（真 NFS）12514ms vs `$HOME_DIR`（ext4）62ms，**约 200 倍**。
真要把仓库放 NFS，用 `git init --separate-git-dir` 把 git 目录留在本地盘。
`cat .git` 应显示路径而非目录。

> 历史：本条原写「实测慢 100~700 倍」，且把 `/mnt/zhangth/projects`
> 描述为 NFS 路径。前者已按实测更新为约 200 倍；后者是错的，已在上表更正。

## 10. 本机探针用 127.0.0.1，别用公网 IP

数值公网 IP 不需要 DNS；DNS 名称的解析失败应与服务本身故障分开判断。
公网可达性单独测。

## 11. 目录黑名单是历史包袱

笔记改为按项目归档后，枚举函数里的 skip 逻辑曾把 `projects/`
一并滤掉 → **首个项目上线即显示 0 篇**，症状像数据丢失。
见到 skip/黑名单，先问「新增的合法目录会不会被它吃掉」。

## 12. 面板有 60 秒缓存 —— 改归属后别急着断言

`kb-proxy.py` 里 `PANEL_CACHE_TTL = 60.0`。移动/改名笔记后立刻查看板，
**面板仍显示旧路径**（且旧链接已 404），看着像「改动没生效」或「缓存污染」，
其实只是 60 秒没到。

**纪律：改笔记归属后，面板断言等>60s 再验。**
需要立即生效就重启代理，否则别把恢复期当回归。

## 13. 非交互 ssh 的 PATH 与当前目录

export PATH="$HOME/.local/bin:$PATH" 本身有效；若脚本只在当前目录，
当前目录通常不在 PATH，仍会报 bb-ports.sh: command not found。
用 bash bb-ports.sh refresh 或绝对路径。

## 14. 笔记的写路径不在 6424 上

6424 是**故意只读**（只有 GET 路由）。要写笔记有两条路：
- **Basic Memory MCP（8765）**：含 `write_note` / `edit_note` /
  `delete_note` / `move_note`
- 直接改 `$PLATFORM_ROOT/memory/**/*.md`（source of truth，入 git）

> 探MCP 工具清单必须先 `initialize` 拿 `mcp-session-id` 响应头，
> 裸调 `tools/list` 报 `Missing session ID`。
> 另外 `basic-memory --help` **没有** write 子命令，别据此以为不能写。

## 15. 改笔记归属要同时清注册表

笔记移出某目录后，`ports.json` 里对应的 `note_subdirs` 会变成**悬空引用**。
两边必须一起改，否则注册表与磁盘不一致。
