# 上游组件参考（四个 GitHub 来源）

> 2026-10-06 实测核实。**记录本平台的真实用法**，不是上游 README 的转述 ——
> 上游文档不含我们的端口、路径与已知偏差。
> 探测手段：`git remote -v`、`openapi.yaml`、运行时 `tools/list`、`--help`。

## 组件与位置

| 组件 | 上游仓库 | 本平台位置 | 端口 |
|---|---|---|---|
| TencentDB Agent Memory | `TencentCloud/TencentDB-Agent-Memory` | `$TDAM_DIR` | 8421 |
| Basic Memory | `basicmachines-co/basic-memory` | conda env `basic-memory` | 8765 |
| codebase-memory-mcp | `DeusData/codebase-memory-mcp` | `$CBM_DIR/` | UI 9749 |
| Backlog.md | `MrLesk/Backlog.md` | `~/.local/bin/backlog` | 6420/6422/6423 |

**仓库名区分**：`tencentdb-agent-memory` 与实际远端 `TencentDB-Agent-Memory`
（**大写 TDAM**）是同一项目。其 `package.json` 自述
"Standalone knowledge service — Code-Graph + LLM-Wiki engine"——
平台的 wiki 与 code-graph 两个能力都出自它。

## A. TencentDB Agent Memory（8421）

Node 服务，`ExecStart=$NODE_BIN dist/server.mjs`，MIT。
HEAD 8b86874。

**API 前缀是 `/v3`**，不是 `/v3/knowledge`。拼接时注意双斜杠
（`BASE=/v3` + `endpoint=/wiki/get` → 必须 `lstrip("/")`）。

| 响应形态 | 含义 |
|---|---|
| 纯文本 `404 Not Found` | 请求**没进应用** —— 路径写错 |
| JSON `{"code":...}` | 请求**已进入应用** —— 业务错误 |

`openapi.yaml` 共 **28 个端点**（全 POST）：

- wiki 组 14：`/v3/wiki/{create,get,list,ingest,delete}`、
  `raw/{ls,read,write,rm}`、`page/{ls,read,write,rm}`、`graph`、`search`
- code-graph 组 14：`/v3/code-graph/{create,list,get,sync,delete,search,explore,callers,callees,impact,node,status,files}`

必填头：`x-tdai-service-id: <TEAM_SLUG>` + body 含 `"team_id": "<TEAM_ID>"`；
写/管理端点另需 `Authorization: Bearer $KNOWLEDGE_SERVICE_KEY`。

```bash
curl -s -X POST http://127.0.0.1:8421/v3/wiki/get \
  -H "x-tdai-service-id: <TEAM_SLUG>" -H "Content-Type: application/json" \
  -d '{"team_id": "<TEAM_ID>","wiki_id":"<WIKI_ID>"}'
```

### 负控更正（实测推翻旧说法）

|旧认知 | 实测 |
|---|---|
| 错误 `service_id` → 404 | **400 `wiki_id is required`**（缺鉴权头仍进应用，先被参数校验挡） |
| 可用错误 Bearer key 做负控 | 无效 —— 只读白名单里错误 key 仍可能 200 |

`/v3/code-graph/status` 返回 **401 `valid service key required`**。

### 本平台的 code-graph 事实

`/v3/code-graph/list` 返回 `{"items":[],"total":0}` —— **从未在 8421 建过 code-graph**。
`state/codebase-memory/` 下是 `*.db.pre-migration` 后缀，图谱数据**尚未完成迁移**。

6424 展示的 3 个 HTML 图谱是 `vcc-readonly.py` 的 `/api/codegraph` 读的
**预渲染静态快照**（自研 HTML，无 d3/cytoscape）。**与 8421 code-graph API 是两条独立路径**。

## B. Basic Memory（8765）

版本 0.23.2。`~/.basic-memory/config.json` 中 `vcc-notes` 指向
`$PLATFORM_ROOT/memory` 且为 `default_project` ——
**通过 8765 写入的就是 memory 仓库文件（真源）**。

探工具清单**必须先 `initialize` 拿 `mcp-session-id` 响应头**，
裸调 `tools/list` 报 `Missing session ID`。`basic-memory --help`
**没有** write 子命令，别据此以为不能写。

运行时实测 **21 个工具**的真实必填参数（README 多数未披露）：

| 工具 | 必填 |
|---|---|
| `write_note` | `content`, `directory`, `title` |
| `edit_note` | `content`, `identifier`, `operation` |
| `read_note`/`view_note`/`delete_note`/`move_note` | `identifier` |
| `read_content` | `path` |
| `build_context` | `url` |
| `create_memory_project` | `project_name`, `project_path` |
| `search`/`fetch` | `query`/`id` |
| `search_notes`/`schema_validate` | 无必填 |

`write_note` 需**同时**给三个参数，少 `directory` 直接 422。
所有工具支持 `output_format="json"`。

笔记格式：

```markdown
---
title: <标题>
type: note
permalink: <uri-slug>
tags: [可选]
---

## Observations
- [fact] 某个事实 #标签

## Relations
- relates_to [[另一个实体]]
```

裸链接 `- [[目标]]` 索引为 `links_to`。语义搜索用 FastEmbed
（默认 `bge-small-en-v1.5`），reranker 默认**关闭**。

**写笔记优先用 8765 MCP 或直接改memory 目录，6424 故意只读。**

## C. codebase-memory-mcp（UI 9749）

静态单文件二进制 `$CBM_DIR/codebase-memory-mcp`。
图谱持久化在 `~/.cache/codebase-memory-mcp/`（SQLite/WAL）。

上游 **17 个 MCP 工具**，核心：

| 工具 | 用途 |
|---|---|
| `index_repository` | `repo_path` 用**绝对路径**；大仓库 `async=true` + 轮询 `status=true` |
| `list_projects` | 列已索引项目（无参数） |
| `get_graph_schema` | **先调这个** |
| `search_graph` | `name_pattern` 正则 + `label`、BM25、语义 |
| `trace_path` | `direction` = inbound/outbound/both，`depth` **1–5** |
| `get_code_snippet` | qualified name 格式 `<project>.<path_parts>.<name>` |
| `get_architecture` | 语言/包/入口/路由/热点/边界/层 |
| `query_graph` | 只读 openCypher；`MERGE` 返回 `unsupported`（**不静默返回空**） |
| `detect_changes` | git diff → 受影响符号与风险 |

图谱涵盖声明结构（`Class`/`Function`/`Method`/`Route`/`Resource`）、
关系（`CALLS`/`IMPORTS`/`INHERITS`/`TESTS`/`DATA_FLOWS`）、
跨服务（`HTTP_CALLS`）、派生分析（dead code、Louvain、`SIMILAR_TO`）。

```bash
codebase-memory-mcp config set auto_index true
codebase-memory-mcp config set watch_non_git true
codebase-memory-mcp --ui=true --port=9749   # 多agent 共用一个 daemon
```

**重要限制**：`check_index_coverage` clean 只意味着"没记录到索引缺口"，
**不是完整性证明**。声称"没有调用者""死代码"前仍须查源码。
工具**不含 LLM**也不要 API key，自然语言理解由 MCP 客户端负责。

**`.codebase-memory/graph.db.zst` 不要每次 watcher 更新都提交 git**（会让仓库膨胀到 GB）。

## D. Backlog.md

版本 1.53.0，路径 `~/.local/bin/backlog`。
非交互 shell 需先 `export PATH="$HOME/.local/bin:$PATH"`。

**读任务用 `backlog task view <id>`，是 `view` 不是 `show`。**

顶层命令：`init task search draft milestone board doc decision agents
config doctor cleanup browser overview completion instructions mcp help`

`task` 子命令：`create list edit view archive complete demote`
（**没有**独立 `status` 命令，状态通过 `edit -s` 改）。

```bash
backlog instructions overview      # 开工先读
backlog task create "标题" -d "描述" --ac "验收标准" --notes "踩坑"
backlog task list --plain
backlog task view TASK-2
backlog task edit TASK-2 -s "In Progress"
backlog board                      # 终端看板
```

配置查找：`backlog.config.yml`（规范）→ `backlog/config.yml` →
`.backlog/config.yml`。本平台用后者，其中 `auto_commit: false` +
`filesystem_only: true` —— **这就是 platform-core 不在 git 的原因**。

无 git 项目用 `backlog init "名字" --no-git`（强制关闭分支检查与远程操作）。

**`backlog browser` 只监听 127.0.0.1**，不暴露给局域网或 VPN。
本平台不用它（看板由 `vcc-backlog` 在 6420/6422/6423 提供）。

## E. 协作关系

```
笔记真源 memory/projects/<project>/*.md
   ├─(Basic Memory 8765 MCP / 直接改文件)
   │     → health_check --deep 检测到比 wiki 新 → 报 deep/wiki-freshness
   ├─(手动搬到 wiki raw/sources/) → POST /v3/wiki/ingest → 6424 展示
代码仓库 platform/
   ├─(codebase-memory-mcp 索引) → 预渲染 state/codegraph/*.html → 6424 /api/codegraph
   └─(backlog CLI)→ platform-core/.backlog/tasks/*.md → 6420/6422/6423 看板
```

**三层互不自动传导**：改笔记不更新 wiki；改代码不更新图谱；
改任务不更新其他层。每次都要显式搬运 + 显式重建。

## F. 本次更正的错误认知汇总

| 旧说法 | 实测结论 |
|---|---|
| 错误 service_id → 404 | **400 `wiki_id is required`** |
| `/v3/wiki/get` 可用错误 key 负控 | 只读白名单，无效 |
| `write_note` 很简单 | 必填三个参数，少 `directory` 就 422 |
| help 无 write 就没有写能力 | MCP 有 `write_note`，只是 CLI 没 |
| 图谱来自 8421 code-graph API | API 返回空；HTML 是自研快照，两条路径 |
| `backlog task show <id>` | 是 `backlog task view` |
| `backlog browser` 可远程访问 | 只绑 127.0.0.1 |
